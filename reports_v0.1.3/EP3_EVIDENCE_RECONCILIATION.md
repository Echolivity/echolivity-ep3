# EP-3 v0.1.3-dev — Evidence reconciliation (Workstream E)

## The discrepancy

The v0.1.2-dev package had two different D2 ("ride into oscillation") results:

| Location in v0.1.2-dev package | D2 values |
|---|---|
| `remediation/evidence_v0.1.2/dub_scenarios.log` | oscillation −50.5 dBFS RMS, spread 42.6 dB, recovery `None` |
| `tests/dub_scenarios_results.json`, `tests/DUB_SCENARIO_REPORT.md`, team review | −24.0 dBFS, spread 10.6 dB, plateau after 0.8 s, recovery 3.95 s (1/8 dotted); −18.2 dBFS, 0.4 dB, 0.9 s, 0.65 s (114 ms) |

## Cause (provenance)

There were two different scenario definitions.
- **The first D2:** Sustain was raised only after the repeats had died, so the loop had to build from tape hiss. It never reached a steady state in the render window, which explains the −50.5 dBFS level and 42.6 dB spread.
- **The redefinition:** that isn't how a dub engineer rides feedback, so D2 was redefined before v0.1.2-dev was delivered. The new version rides Sustain 0.6 → 0.95 while the repeats are still sounding, at two delay times.
- **The leftover:** the replacement was re-run on its own and its numbers were merged into the JSON and report. The evidence log was not regenerated, so it kept the first run's lines.

## Verification (re-run)

The whole scenario set was re-run in one pass on the unchanged engine (sha256 daa947e8…ecaef1d8):
- **Command:** `python3 tests/dub_scenarios.py`
- **Log:** `remediation/evidence_v0.1.3/dub_scenarios.log`

Result:
- **D2** reproduces −24.0 dBFS / 10.6 dB / 0.8 s / 3.95 s and −18.2 dBFS / 0.4 dB / 0.9 s / 0.65 s exactly.
- **D1 and D3–D9** reproduce the v0.1.2-dev values exactly.
- **D6** gained click and recovery metrics; **D10** is new. Both are reported in `tests/DUB_SCENARIO_REPORT.md`.

**Authoritative:** the −24.0 dBFS / 10.6 dB result (redefined scenario), now backed by a single consistent run.
